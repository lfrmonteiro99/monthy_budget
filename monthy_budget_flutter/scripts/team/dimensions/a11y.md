## Dimensão: a11y — a app é utilizável por quem não a vê como tu

Duas fontes: a **árvore semântica** (programático) e os **screenshots**
(contraste e tamanho percebido).

```javascript
import { launch, close, openTab, semantics, layoutSuspects } from './flutter_driver.mjs';
const s = await launch({ url: '__APP_URL__' });
for (const tab of ['home','track','shop','more']) {
  await openTab(s.page, tab);
  const nodes = await semantics(s.page);
  console.log(tab, 'sem nome:', nodes.filter(n => !n.label).length);
  console.log(tab, JSON.stringify(await layoutSuspects(s.page), null, 1));
}
await close(s);
```

O que procurar:
- **controlos sem nome acessível**: `role=button`/`tab` sem `aria-label`. Um
  leitor de ecrã anuncia "botão" e mais nada. Reporta quais.
- **rótulos inúteis**: `aria-label` que é o texto do ícone ("mais_vert") ou uma
  chave de tradução em cru (`dashboard_open_settings`) em vez de linguagem
  humana. Uma chave de i18n exposta como rótulo é sempre defeito.
- **alvos de toque pequenos**: menos de 44x44 px (vem em `layoutSuspects` como
  `small-tap-target`). Confirma no screenshot que é mesmo um controlo.
- **contraste**: olha para os screenshots, em `light` **e** `dark`. Texto
  cinzento-claro sobre branco, texto sobre imagem/cor sem camada de
  legibilidade, estados desactivados indistinguíveis de activos.
- **informação só por cor**: um valor positivo/negativo distinguido apenas por
  verde/vermelho, sem sinal nem ícone.
- **ordem de foco**: navega com `Tab` e confirma que o foco percorre o ecrã numa
  ordem lógica e que é **visível** onde está.
- **texto ampliado**: com viewport `small`, verifica se o texto continua a
  caber e a ser legível.

Reporta em bloco quando o defeito é sistémico (ex: "todos os botões de ícone da
barra superior não têm rótulo") em vez de um finding por botão — é o mesmo
problema e o mesmo fix.
